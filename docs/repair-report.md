## 一、项目定位

一个**自托管的番剧自动追更器**：按订阅的 mikan RSS 定时检查新集 → 解析磁力/种子 → 按模板重命名并拼出保存路径 → 推送到 qBittorrent 下载 → 提供 Web UI 做订阅/下载/日志/设置管理。

## 二、修掉的问题

接手时这些缺陷都是**实测可复现**的，不是理论风险。按严重度排：

### 🔴 安全类（会造成不可恢复的数据损失）

**1. 删除订阅可被同网段任意设备触发，且会真删 NAS 文件**
服务监听所有网卡，而 `POST /api/sub/delete` 无任何鉴权。任何一台连着 WiFi 的设备（甚至一个被访问的恶意网页通过 CSRF）都能删掉订阅并连带删除 `/media` 里的正片。
→ 改为**强制登录**：新增登录页 `/login` 与首次注册页 `/setup`，远程访问必须先有会话 Cookie 或 API Key，否则页面 302 跳登录、接口 401；本机（`127.0.0.1`/`::1`）免登录便于运维。原 `admin_token` 方案已完全移除（它无法在 WebUI 里设置，实际用不起来）。

**2. `save_path` 路径穿越**
`save_path` 传 `../../media/新番追更/x` 就能写到白名单目录之外。
→ `cleanSavePath()` 统一做 `path.Clean` 归一化（消解 `..`、`//`、`.`、尾斜杠），拒绝 `%2e`/`%2f` 编码分隔符，再校验白名单前缀。

**3. 删除确认只在前端做**
直接 `curl POST /api/sub/delete` 就能删掉文件，前端那个"输入番名确认"形同虚设。
→ 服务端强校验 `confirm_title` 与订阅标题一致才允许连带删文件。

**4. 删除订阅会误删同系列/同字幕组其他番的文件**
`MatchTasks` 用宽松的名称包含去匹配 qB 任务，导致删一个订阅连坐删别人的文件。
→ 重写匹配逻辑：按规范化后的保存路径 + 季号 + 集数锚定，`isSeasonSibling` 处理 `Season 2`/`S2`/`第二季` 等写法，无把握时宁可少删。

### 🟠 正确性类（会静默丢集 / 覆盖错文件）

**5. 集数识别漏判（本轮新增修复）**
真实源里这些命名被判"无法识别集数"，资源永远推不下来且**没有任何报错**：
- `... Kurumi-chan - 03 (ABEMA 1920x1080 ...)` —— 数字后跟 `(`，旧规则不认
- `... - 09v2 [1080p]` —— 带版本号后缀，旧规则不认
- `... EP10 [1080p]` —— `EP` 形式完全没规则

→ 补强 `defaultEpPatterns`：`- NN` 允许后跟 `(` 和 `v2/v3`；新增 `EP` 规则（要求带 P，避免把单独的 E 误判）。同时加了 13 条真实命名回归用例 `episode_test.go`，并确保分辨率数字不会被吃成集数。

**6. 剧场版被当普通集数丢弃**
`IsMovie` 只认 `[MOVIE]`/`[剧场版]`，导致 `[LinRip] 超时空辉夜姬！ [BDRemux ...]` 这类被判"无法识别集数"永久丢弃。
→ 扩充判据：`劇場版`/`映画`/`BDRemux`/`BDMV` 等压制组惯用特征。

**7. 推送路径与匹配路径算法不一致**
`check.go` 手写变量拼路径，绕过了 `render.go` 的唯一出口，尾斜杠/双斜杠会让"推送路径"和 `MatchTasks` 算出的路径对不上，于是删任务时匹配不到。
→ 全部收敛到 `RenderSavePath`/`RenderRename` 单一出口。

**8. `State.Get` 返回内部指针**
调用方拿着裸指针在锁外读写 map 里的状态，与并发 `Update` 竞态，可能读到撕裂的 struct 甚至 panic。
→ 改为返回值拷贝，所有写入走 `Update()` 闭包。

**9. 订阅添加无锁**
`handleSubscribe` 直接 append 到 `cfg.Subscriptions`，与定时检查并发时可能丢订阅。
→ 加锁 + 切片 `[:idx:idx]` 三索引切片避免底层数组被复用。

### 🟡 可靠性类

**10. 状态文件非原子写** —— 断电/崩溃会写坏 `state.json`，重启后全部订阅变成"首次运行"从而重复下载整个历史。→ 改为临时文件 + `rename` 原子替换。

**11. 服务无内存上限** —— 加了 systemd `MemoryMax=128M`、`Restart=always`、`RestartSec=15`，异常退出自动拉起。

### 🟢 体验类

**12. UI 缺字段** —— 订阅表单补上保存路径模板、重命名模板、集数正则、总集数等字段。

**13. 本轮新增：登录页 + API Key**
`admin_token` 方案作废（服务端存了也没地方方便地改）。现在改为：首次访问 `/setup` 建账号密码，之后 `/login` 登录，登录后即拥有全部权限；同时为该账号自动生成一个 API Key（可在设置页重置），供 AI / 脚本用 `X-API-Key` 或 `Authorization: Bearer` 远程调用。密码以 PBKDF2-SHA256 加盐哈希保存，页面与接口均不回显。

## 四、运维须知

### 登录账号与 API Key

服务现在**必须先登录**才能用（原有的 `admin_token` 方案已整体移除）。

**首次使用**：浏览器打开 `http://192.168.50.68:7788/` → 自动跳到 `/setup` → 填账号、密码（至少 6 位）、再确认一次 → 创建后直接进入主界面，**拥有全部权限**，无需再做任何配置。

**日常登录**：打开地址 → 跳到 `/login` → 输账号密码 → 进入主界面。登录状态由 `HttpOnly` + `SameSite=Lax` 的会话 Cookie 维持，默认 7 天有效，勾「记住我」可延长到 30 天。右上角「退出」即可注销。

**API Key（给 AI / 脚本远程调用）**：设置页 →「账号与 API Key」卡片。
- 首次注册时自动生成，也可随时点「重置 API Key」（旧 Key 立即失效）
- 调用方式二选一：
  ```bash
  curl -H "X-API-Key: <你的key>" http://192.168.50.68:7788/api/subs
  curl -H "Authorization: Bearer <你的key>" http://192.168.50.68:7788/api/subs
  ```
- API Key 拥有**和登录账号完全相同的权限**，等同于密码，别贴进公开仓库。

**忘了密码**：删掉账号文件让服务回到首次注册状态，然后在浏览器重新设置：

```bash
rm /opt/anime-go/auth.json && systemctl restart anime-go
```

**本机免登录**：从 `127.0.0.1` / `::1` 发起的请求直接放行（方便命令行运维），远程访问一律要求登录或 API Key。

**账号存放**：`/opt/anime-go/auth.json`，权限 `600`，密码用 PBKDF2-HMAC-SHA256（12 万次迭代 + 随机盐）存储，**不存明文、不存可逆密文**；全站任何接口、页面都不会回显密码或 Key。

├── anime-go            运行中的二进制
├── config.json         生产配置（订阅、qB 凭据、白名单）

## 五、还需要你知道的两件事

1. **首次订阅的默认行为变了**：现在默认把 RSS 里现存的**全部历史集**都下载一遍（你之前的要求），只追新集要显式勾 `skip_backfill`。UI 上已有说明。

2. **`force` 检查不会重复推送**：已经推过的集数会被去重跳过，这是刻意的（避免重复下载）。所以"立即检查"看到"推送 0 条"通常是正常的，不是故障。
